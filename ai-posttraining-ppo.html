1.1 PPO：RL 的主力算法

首页 > AI > Training > 1.1 PPO

1. PPO 是什么

PPO（Proximal Policy Optimization）是 RLHF 中最经典的强化学习优化算法。

在 LLM 训练中，模型本身就是策略（Policy）：prompt 可以看作状态，模型生成的 token 序列可以看作动作。

一句话理解：PPO 让模型朝着更高奖励的方向更新，但每一步都不能走得太猛。

2. PPO 的更新目标

PPO 的目标是让策略朝着更高奖励的方向更新，同时通过 clipping 机制限制新旧策略差异，避免一次更新幅度过大导致训练不稳定。

这个 clipping 机制是 PPO 稳定性的关键：当新策略相对旧策略变化过大时，目标函数会被截断，从而避免训练过程中策略突然偏离太远。

3. PPO 损失函数

最常见实现（OpenAI / TRL 风格）会把 KL 惩罚并入每个 token 的 reward，因此总损失通常写成：

\[ L_{\mathrm{PPO}} = L_{\mathrm{clip}} + c_1 L_{\mathrm{value}} \]

其中：

  • KL 惩罚：已经并入每个 token 的 reward，不再单独写成一个 loss 项。
  • 价值损失 \(L_{\mathrm{value}}\)：一般采用 MSE，用来训练 Value Model / Critic。

裁剪项的核心形式如下：

\[ L_{\mathrm{clip}}(\theta) = \mathbb{E}_t \left[ \min\left( r_t(\theta)\hat{A}_t,\, \operatorname{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t \right) \right] \]

3.1 变量说明

  • \(r_t(\theta)\)：新策略与旧策略在第 \(t\) 个 token 上的概率比。
  • \(\hat{A}_t\)：优势函数，表示当前动作相对平均水平好多少。
  • \(\epsilon\)：clip 范围，通常取 0.1 到 0.2，用来限制策略更新幅度。

4. LLM 训练中的四个模型

PPO 在 LLM 训练中需要同时维护四个模型：

模型 角色 是否更新 说明
Policy Model 被训练的 LLM 是 生成回答，是我们最终要得到的模型
Reference Model 初始策略的冻结副本 否 用于计算 KL 散度，防止策略偏离太远
Reward Model 评估回答质量 否 对生成的完整回答打分
Value Model (Critic) 估计状态价值 是 用于计算 Advantage，即“这个回答比平均水平好多少”

5. 主要问题

PPO 需要同时加载四个模型，显存开销巨大；训练过程中需要在生成（rollout）和更新之间反复切换，工程复杂度高；同时它对超参数比较敏感，调参难度也更高。
