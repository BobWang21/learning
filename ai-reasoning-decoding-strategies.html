解码策略 (Decoding Strategies)

1. 解码策略是什么

LLM 解码策略属于推理阶段（Inference / Test-Time Compute）知识，不更新模型参数。它解决的问题是：模型已经输出 logits 后，如何选择下一个 token。 它在普通生成中影响回答的稳定性和多样性；在 Reasoning 模型中还影响搜索路径、候选答案选择和 Test-Time Scaling 效果。

2. 基本生成过程

每一步生成，模型大致经历：logits → (可选调整) → softmax → 概率分布 → 解码策略 → 下一个 token。例如模型输出的概率分布为：A(0.50)、B(0.25)、C(0.15)、D(0.07)、E(0.03)。注意：Temperature、Top-k、Top-p、Repetition Penalty 属于采样/概率分布控制参数，通常和 Sampling 一起使用；Greedy、Beam Search、Best-of-N、Self-Consistency 属于完整生成策略。

3. 常见策略

3.1 完整策略

解码策略 核心思想 优点 缺点 适合场景
Greedy 每步选概率最高的 token 稳定、快、可复现 缺少多样性，容易局部最优 事实问答、代码、JSON、抽取
Sampling 按概率随机采样 token 多样，能探索不同表达 不稳定，可能采到低质量 token 聊天、创意写作、多路径推理
Beam Search 同时保留多条高概率序列路径 比 Greedy 更全面 成本高，输出可能死板 翻译、摘要、结构化生成
Best-of-N 生成 N 个候选，用评分器选最好 提高复杂题正确率 成本约增加 N 倍，依赖评分器 数学、代码、Reasoning
Self-Consistency 生成多条 CoT，最终答案多数投票 提高推理稳定性和准确率 成本高，仅适合答案可聚合任务 数学、逻辑、选择题

3.2 控制参数

参数 核心思想 注意事项 常用范围
Temperature 调整概率分布的平滑度。接近 0 趋近 Greedy，越高越随机 过高会胡编，过低会死板 0.0 ~ 1.0，创意任务可到 1.2
Top-k 只从概率最高的 k 个 token 中采样 固定 k 不够自适应 30 ~ 50（OpenAI 推荐）
Top-p 从累计概率达到 p 的最小 token 集合中采样 比 Top-k 自适应，p 过高仍可能引入噪声 0.9 ~ 1.0
Repetition Penalty 降低已出现 token 的概率 过强会伤害正常表达 1.0 ~ 1.2

3.3 随机种子（Seed）

相同输入、相同解码参数，若 Seed 不同，Sampling 结果也会不同。工程上设置固定 Seed 可保证结果可复现；实验中固定 Seed 是排除随机干扰的标准做法。

4. 场景速查表

Greedy / Temperature → 0 适合“有标准答案、格式严格、需要稳定复现”的任务；需要探索多种可能时，才提高随机性或多次采样。

场景 推荐策略
数学 / 代码 / 事实问答 Greedy 或 Temperature → 0
创意写作 Temperature 0.7-0.9 + Top-p 0.9-1.0
普通聊天 Temperature 0.5-0.8 + Top-p 0.9-1.0
长推理 多次采样 + Self-Consistency
有 Verifier 的任务 Best-of-N
翻译 / 摘要 Greedy / Beam Search / Low Temperature
严格 JSON 输出 Temperature → 0

6. 解码策略与慢系统推理（Reasoning）的关系

慢系统推理不是一次生成答案，而是通过解码策略进行更多搜索、验证和选择。

慢系统方法 与解码策略的关系
Long CoT 允许或诱导模型生成更长的推理链
Self-Consistency 需要多次采样生成多条推理链
Best-of-N 需要生成多个候选答案供选择
Tree-of-Thought 每一步需要解码生成多个分支
Verifier 先生成候选，再选择最优
Reflection 生成答案后，再生成检查和修正
Test-Time Scaling 本质是增加推理时的采样、搜索、验证计算

7. 一句话总结

解码策略属于推理阶段知识，核心是控制模型如何从概率分布中选择下一个 token。普通生成中它影响稳定性和多样性；Reasoning 模型中它还影响搜索路径、候选答案选择和 Test-Time Scaling 效果。完整策略与控制参数组合使用，才能达到最佳效果。
